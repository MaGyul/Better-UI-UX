# 에디터 현황 분석과 개선 제안

M3 에디터를 만들면서 쌓인 피드백과 코드 상태를 바탕으로, 지금 부족한 점과 다음에 할 만한 일을 정리했다.
우선순위: **P0** 쓰다 보면 반드시 막히는 것 / **P1** 있으면 체감이 큰 것 / **P2** 다듬기·확장.
규모: **S** 반나절 이내 / **M** 1~2일 / **L** 며칠 이상.

## 1. 지금까지 된 것 (요약)

- 원본 XML 텍스트 패치(주석·들여쓰기 보존) + 실행 취소/다시 + 핫리로드 연동
- 스크래치식 블록 끌어다 놓기, 접히는 구조 트리, 드래그 이동/8방향 리사이즈, 스냅·정렬선·8px 격자
- 부모 밖으로 못 나감, 가장자리 자동 기준점(anchor), row/column 최소 크기, 내용에 맞춰 컨테이너 자동 확대
- 속성 패널(채팅식 텍스트 편집, 클릭 이벤트 자동 완성, 컬러피커 + 직접 입력), IME 조합창
- 화면 이동/Fit, 화면 경계 표시, 패널·툴바 접기 + 가장자리 호버로 임시 표시, 접힘 상태 config 저장
- 호버/눌림 색, 마우스 포인터 변경, 저장 확인 창, 알림 토스트, 스크롤하는 안내 문구, 템플릿(`<use>`) 편집

## 2. 편집 기능에서 빠진 것

| 우선 | 규모 | 항목 | 왜 필요한가 |
|---|---|---|---|
| P0 | M | **요소 복사/붙여넣기**(Ctrl+C/V, 다른 부모에 붙이기) | 지금은 같은 부모 안 복제(Ctrl+D)만 된다. 비슷한 요소를 여러 곳에 만들 때 필수 |
| P0 | M | **감싸기/풀기**(선택을 row/column/panel 로 감싸기, 컨테이너 해제) | 레이아웃을 바꿀 때 트리에서 끌어 옮기는 것보다 훨씬 자연스럽다 |
| P0 | S | **속성 값 종류별 편집기**: anchor/justify/align 는 드롭다운, `true/false` 는 체크박스, 숫자는 ± 와 드래그 조절 | 지금은 전부 글자로 쳐야 해서 오타·잘못된 값이 생긴다 |
| P0 | M | **저장 전 XML 오류 처리 강화**: 오류 줄 표시, 직전 정상 상태로 한 번에 복귀 | 자동 완성/피커로 값을 넣다가 깨질 수 있다 |
| P1 | M | **다중 선택**(Shift/Ctrl 클릭, 박스 선택) + 한꺼번에 이동·삭제·정렬 | 여러 요소를 같이 옮기는 작업이 불가능 |
| P1 | M | **정렬/분배 도구**(왼쪽/가운데/오른쪽, 균등 간격) | 숫자 입력 없이 배치를 맞출 수 있다 |
| P1 | S | **요소 잠금/숨김 토글**, 트리에서 이름(id) 더블클릭 변경 | 겹친 요소·배경 패널을 건드리지 않고 작업 |
| P1 | M | **z-order(앞/뒤로 보내기)**: 같은 부모 안 순서를 버튼/단축키로 | 지금은 방향키로 flow 순서만 바꿀 수 있고 stack 계열은 불가 |
| P1 | L | **스타일시트 편집**: 계산된 값이 어느 규칙에서 왔는지 표시, 규칙/클래스 편집 | 지금은 값이 스타일시트에서 오면 인라인에만 쓴다. 테마 작업이 불편 |
| P1 | M | **상태 미리보기**(`:hover` `:active` `:disabled` 강제 표시) | 에디터 중에는 호버/클릭 효과가 꺼져서 상태 스타일을 못 본다 |
| P1 | M | **해상도/GUI scale 미리보기**(창 크기 프리셋, 1~4배) | 같은 XML 이 해상도마다 어떻게 보이는지 확인 |
| P1 | M | **리소스 선택기**: 이미지·아이템·폰트·언어 키 고르기(`src` 칸) | 지금은 경로를 직접 쳐야 한다 |
| P2 | M | **템플릿 추출**("선택을 템플릿으로 만들기") | 반복 요소를 `<template>`+`<use>` 로 정리 |
| P2 | L | **애니메이션/transition 편집**, 타임라인 미리보기 | M2.5 기능을 에디터에서 다룰 수 없다 |
| P2 | S | **raw XML 보기**(읽기 전용 → 이후 편집) | 에디터가 못 하는 편집은 파일을 열어야 한다 |
| P2 | S | **변형(transform) 요소의 히트 테스트** | 회전/스케일된 요소는 지금 클릭이 어긋난다(알려진 한계) |

## 3. 사용성 / 기본 UI 개선

- **P0 · S — 단축키/도움말 오버레이**: `F1` 또는 `?` 로 조작표(드래그·휠·Ctrl 조합)를 한 장으로. 지금은 하단 안내 한 줄뿐이라 처음 쓰는 사람이 기능을 못 찾는다.
- **P0 · S — 속성 패널 스크롤/섹션 접기**: 행이 많아 작은 창에서는 아래 속성이 잘린다(`y + ROW_H > viewH` 에서 그리기를 멈춤). 스크롤과 "레이아웃/모양/동작" 그룹 접기가 필요.
- **P1 · S — 구조 트리 검색/필터, 드래그 중 자동 스크롤**: 요소가 많아지면 트리 이동이 어렵다.
- **P1 · M — 패널 너비 조절, 확대/축소(줌)**: 고정 폭(140/142px)이라 긴 값이 `…` 로 잘리고, 작은 요소는 정밀하게 잡기 어렵다.
- **P1 · S — 룰러와 끌어서 만드는 가이드선, 요소 사이 간격 표시**(Alt 누르면 인접 요소까지 거리).
- **P1 · S — 툴팁**: 툴바 버튼(Grid, Anchor:auto/keep, Fit)의 의미가 이름만으로는 불분명하다.
- **P1 · M — 실행 취소 기록 패널 / 자동 저장·백업**: 게임이 죽어도 편집 내용을 잃지 않게 `.bak`/임시 저장.
- **P1 · M — 화면(XML) 전환기**: 에디터 안에서 다른 UI 열기, **새 UI 만들기**(빈 screen / 템플릿 갤러리). 지금은 `/uiux edit <id>` 로만 시작.
- **P2 · S — 접근성**: 색 대비(`C_DIM` 글자), 키보드만으로 패널 이동(Tab 순서), 큰 글꼴 옵션.
- **P2 · S — 문구 현지화**: 에디터 문구가 한글로 하드코딩돼 있다. 언어 파일(`lang`)로 빼면 영어 등 지원 가능.
- **P2 · S — 마지막 상태 복원**: 선택한 요소, 화면 이동 위치, 접힌 트리 행도 config/세션에 저장(패널/툴바 접힘은 이미 저장).

## 4. 안정성 / 기술 부채

| 우선 | 항목 | 내용 |
|---|---|---|
| P0 | **NeoForge·Vulkan 실기 검증** | 에디터는 Fabric(+기본 렌더러)에서만 눈으로 확인했다. NeoForge 런타임, Vulkan 렌더러, OpenGL 호환에서 클립/변환/커서/IME 가 같은지 확인 필요 |
| P0 | **IME 실제 입력 확인** | 조합창은 마인크래프트 기본 오버레이를 연결만 했다. 한글/일본어 입력에서 위치·확정 동작을 실제로 확인해야 한다 |
| P1 | **편집마다 문서 전체 재로드** | 현재 모든 편집이 파싱+레이아웃을 다시 한다(작은 문서에선 문제없음). 큰 화면에서는 드래그 중 프레임이 떨어질 수 있어 증분 갱신/디바운스 필요 |
| P1 | **외부 변경 충돌** | 에디터 중에는 핫리로드를 무시한다. 다른 편집기로 같은 파일을 고치면 저장 시 덮어쓴다 → 저장 시 파일 변경 감지 + 병합/경고 |
| P1 | **패널 overflow 자식** | 작은 패널 안의 자식이 패널보다 클 때 편집 방법이 없다(알려진 한계) |
| P1 | **`<use>` 편집 한계** | `<use>` 는 매개변수만 고칠 수 있고, 크기·위치 편집은 `<use>` 에 쓰여 템플릿 결과에 반영되지 않을 수 있다. 템플릿 쪽 값 편집/매개변수 노출 UI 필요 |
| P1 | **테스트 자동화** | 에디터 로직은 단위 테스트 241개가 있지만 화면 결과는 눈으로만 확인한다. 드로우 리스트 골든 파일(스냅샷)로 레이아웃 회귀 방지 |
| P2 | **코드 정리** | `EditorController` 가 2,000줄 넘게 커졌다. 입력(마우스/키), 패널 그리기, 트리, 속성 편집, 피커/자동 완성으로 분리 |
| P2 | **서버 정책** | 계획의 "서버가 에디터를 막는" 기능(`editorAllowed=false`)이 아직 없다 |

## 5. 이번 세션에서 확인한 사용자 흐름의 빈틈

- 에디터가 켜졌는지/어떻게 끄는지 알 방법이 없었다 → `Exit`, `Esc`, 저장 확인 창으로 보완. 다만 **켜는 방법**(F8, `/uiux edit`)도 화면 안에서 알려 주면 좋다(도움말 오버레이 제안과 연결).
- 요소가 상단 바/패널 뒤에 숨는 문제가 반복해서 나왔다 → 통과 영역, 자동 이동, 임시 표시 패널로 완화했지만 **"모든 요소 목록에서 찾기/보이기"** 가 있으면 근본적으로 해결된다(트리 검색 + 선택 시 항상 보이도록 화면 이동).
- 값을 직접 쳐야 하는 칸이 많다 → 종류별 편집기(드롭다운/체크/스핀)로 줄이면 오류 보고가 크게 줄 것이다.
- 숨기기/호출 UX(툴바·패널)는 같은 규칙(가장자리에 올려 두면 표시)으로 통일됐다. 이후 추가하는 패널(도움말, 기록, 리소스 선택기)도 같은 규칙을 따르게 하면 일관적이다.

## 6. 추천 진행 순서

1. **P0 묶음(약 3~4일)**: 속성 종류별 편집기 → 패널 스크롤/섹션 → 도움말 오버레이 → 복사/붙여넣기 → 감싸기/풀기
2. **검증 묶음(1~2일)**: NeoForge/Vulkan/OpenGL 실행, IME 실입력, 외부 변경 충돌 처리
3. **P1 묶음**: 다중 선택 + 정렬/분배 → 해상도 미리보기 → 상태 미리보기 → 리소스 선택기 → 스타일시트 편집
4. **마무리**: `EditorController` 분리, 골든 스냅샷 테스트, 현지화

가장 먼저 손대면 효과가 큰 것은 **속성 종류별 편집기 + 패널 스크롤**(지금 가장 자주 마주치는 불편)과 **NeoForge/Vulkan 검증**(아직 확인되지 않은 위험)이다.

## 7. 계획에 추가된 것

- **스크립트(JavaScript / GraalVM)**: 요소 수정, CSS 변수 조작, 마인크래프트 명령어 실행만 가능하고 Java 와는 JSON IPC 로만 통신한다.
  자세한 설계와 단계는 [scripting-plan.md](scripting-plan.md). (CSS 변수 Java API `setVariable` 은 이미 구현됨)
